🔭 白盒观测层 — 贯穿所有面板的核心设计原则

核心理念：Agent 不是黑盒 → 每次执行都能看到"它在想什么、做了什么、产出了什么、在哪里操作的"
💭 思考过程
Thinking blocks 实时展示，可折叠查看推理链条，标注 thinking level
🔧 工具调用追踪
每次 tool_use 显示：工具名、输入参数(JSON)、执行结果、耗时、是否审批通过
📂 文件操作记录
read/write/bash 操作的文件路径、diff 预览、工作目录标注
⌨️ 命令执行日志
bash 工具的完整命令、stdout/stderr、退出码、执行时长
🧠 模型调用详情
当前模型、provider、token 用量(input/output/cache)、是否触发 fallback
👶 子 Agent 视图
子 agent 树形拓扑、每个子 agent 的任务/状态/产出/耗时
📦 Session 状态
上下文 token 占比、compaction 次数、消息数、session key
📁 工作区浏览
Agent 工作目录文件树、最近修改文件、附件存储位置

🎨 Tier 1 — 专用交互 UI（7 个面板）

高频 + 可视化 + 强耦合 → 精心设计的交互体验，不接受降级

⬆ 升级
💬
Chat Panel — 对话 + 白盒观测
T1
现状：基础对话（发送/接收/流式/中止），工具调用和 thinking 仅简单折叠展示
升级：成为白盒观测的主界面，对话和执行过程在同一视图中统一呈现
对话流 流式输出 附件上传 审批对话框 工具调用详情面板 文件操作 diff 预览 命令执行日志 thinking 推理链展示 运行状态指示器(模型/tokens/耗时) 子 agent 内联状态
🔭 白盒增强：每条 assistant 消息可展开查看完整执行轨迹 — tool_use 参数+结果、bash 命令+输出、文件读写 diff、token 消耗。不再只是折叠的 JSON，而是格式化的可交互视图。
⬆ 升级
🤖
Agent Workspace — Agent 完整工作台
T1
现状：Agents Panel 只有列表/创建/删除
升级：选中 agent 后展开完整工作台，分 Tab 管理所有维度
Agent 列表/CRUD Model Fallback 链编辑器（拖拽排序） Tool Policy 可视化（5层叠加 + 最终效果预览） Skills 选择器（可用/已启用/过滤） Subagent 配置（depth/concurrent/allowAgents） Sandbox 模式选择器 Identity 预览（avatar/emoji/theme） Bootstrap 文件编辑器
🔭 白盒增强：实时显示 agent 当前状态 — 活跃 session 数、正在运行的任务、最近一次执行的模型/耗时/token。工作目录文件树浏览。
🆕 新增
🔭
Execution Monitor — 执行观测台
T1
全新面板：专门观测 agent 执行过程的独立视图，补充 Chat Panel 的内联观测
实时事件流（lifecycle/tool/assistant/error） 执行时间线（甘特图式） 工具调用瀑布图（调用链可视化） 文件变更汇总（哪些文件被读/写/改） 模型调用统计（调用次数/token/fallback） 子 agent 执行树 Compaction 事件标记
🔭 核心白盒面板：不是在对话中内嵌观测，而是独立的执行观测视角。可以按 runId 回溯任何一次执行的完整轨迹。类似 Chrome DevTools 的 Network/Performance 面板理念。
🆕 新增
🔀
Routing Rules — 路由规则编辑器
T1
全新面板：可视化编辑 AgentBinding 路由规则
规则列表（优先级排序） 条件编辑器（channel + account + peer + role） 匹配测试器（输入消息 → 看命中哪条规则） 拖拽排序优先级
🔭 白盒增强：实时显示最近 N 条消息的路由命中记录，标注匹配了哪条规则、分配给了哪个 agent。
🆕 新增
👶
Subagent Topology — 子 Agent 拓扑
T1
全新面板：子 agent 的树形关系、实时状态、执行产出
父子关系树形图 每个节点：task / model / status / duration 点击节点查看 session 历史 kill / steer 操作 附件传递可视化
🔭 白盒核心：自动化任务分解后，能看到每个子 agent 做了什么、产出了什么、花了多久、用了什么模型。
⬆ 升级
📡
Channel Manager — 渠道管理
T1
现状：只显示渠道连接状态
升级：连接向导 + 多账户管理 + 健康监控
连接状态看板 WeCom 配置向导（4种传输模式选择） Feishu 配置向导（WS/Webhook） 多账户管理 消息吞吐量监控
🔭 白盒增强：每个渠道的最近消息流水、连接断开/重连事件、媒体处理状态。
⬆ 升级
💾
Session Manager — 会话管理
T1
现状：Chat 侧边栏简单列表
升级：独立面板，DM scope 策略可视化，Session 健康度
Session 列表 删除/切换 DM scope 策略选择器（4种图示） Session key 解析展示 上下文健康度（token 用量/compaction 次数） Transcript 预览 + 搜索 Session 导出
🔭 白盒增强：每个 session 的 token 时序图（何时 compaction、何时接近上限），消息统计。

📝 Tier 3 — Schema 自动表单（3 个入口）

快速、准确、可验证 — 不需要复杂交互，config.schema 自动生成表单即可

🆕 新增
⚙️
Advanced Config — 全量配置
T3
全新面板：从 config.schema RPC 自动生成，按 section 分页，覆盖全部 200+ 字段
Schema → Form 自动渲染 按 section 分页（agents/models/tools/...） 实时 JSON Schema 校验 变更 diff 预览 config.patch 回写
🔭 白盒：每次配置修改的审计日志（谁改了什么、何时、旧值→新值）。
⬇ 降级
🔧
Settings → 合并到 Advanced Config
T3
降级理由：现有 Settings 面板只覆盖极少数字段，且都是简单的 key-value。不需要独立面板，合并到 Advanced Config 的 "General" section 即可。
注意：这不是删除功能，是合并到更完整的入口。
⬇ 精简
🏗
Gateway → 精简为状态栏指示器
T3
降级理由：Gateway 健康状态是运维信息，不需要独立面板。精简为顶栏的连接状态指示器（🟢 连接 / 🔴 断开），点击展开详情弹窗即可。不值得占一个导航位。
深度诊断需求：移入 Advanced Config 的 "System" section。
