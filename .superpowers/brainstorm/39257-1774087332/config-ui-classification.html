配置 UI 分级框架

哪些配置需要精心设计的交互 UI？哪些用 Schema 自动表单就够了？

🧭 判断维度：四个问题

🔄
① 操作频率
用户多久调一次这个配置？高频操作值得投入 UI 设计。
每天 每周 首次 几乎不
🔗
② 关联复杂度
改一个字段会影响其他字段吗？有没有组合约束、级联效应？
强耦合 有依赖 弱关联 独立
👁
③ 需要可视化吗
纯数值填写能理解，还是需要"看到"效果？（如路由规则、优先级链）
必须可视化 有帮助 不需要
⚡
④ 误配风险
配错了会怎样？静默失败？服务中断？安全漏洞？风险高需要引导式 UI。
危险 会出错 不理想 无影响

📊 OpenClaw 配置分级结果

🎨 Tier 1 — 专用交互 UI

6 个配置域
需要可视化 + 高频 + 强耦合 → 值得精心设计
🔀
Agent 路由规则 (Bindings)
多条件组合匹配（channel + account + peer + role），需要规则编辑器 + 匹配测试器，纯表单无法表达优先级和条件逻辑
bindings[]match.*
🔗
模型 Fallback 链
顺序敏感的降级链，需要拖拽排序 + 状态指示（哪个 key 在 cooldown），改一个会影响整体可靠性
model.primarymodel.fallbacks[]auth profiles
🔧
工具策略管线 (Tool Policy)
5 层策略的叠加效果难以靠表单理解，需要可视化层叠 + 最终结果预览（这个工具最终是允许还是拒绝？）
tools.allow/deny5-layer pipeline
👶
Subagent 拓扑与控制
父子关系 + 深度限制 + 并发限制 + 工具继承 → 需要树形可视化 + 实时监控
subagents.*maxSpawnDepthallowAgents
💬
Session 策略 (DM Scope)
4 种 scope 策略（main / per-peer / per-channel / per-account）的区别需要示意图 + 选择器
session.dmScopesession.resetTriggers
📡
渠道管理 (Channels)
多渠道 + 多账户 + 各自状态 + 认证流程 → 需要连接状态看板 + 向导式配置
channels.*WeCom/Feishu

🧩 Tier 2 — 增强表单 + 引导

7 个配置域
字段间有耦合关系，需要分组 + 条件显示 + 说明文字，但不需要可视化
📦
Compaction 策略
mode / reserveTokens / keepRecentTokens / maxHistoryShare 互相制约，需要联动表单 + 效果预估
🤖
Agent 完整配置
model + skills + tools + sandbox + identity 组合，需要分 Tab 表单 + 预览
💭
Thinking & Verbose
thinking level 依赖模型能力（xhigh 仅 GPT-5.x），需要条件可选项
⏰
Heartbeat 定时任务
interval + activeHours + target + model 组合，需要时间选择器 + 投递预览
🔒
Sandbox 配置
mode / scope / workspaceAccess 三者耦合，需要组合选择器 + 影响说明
✂️
Block Streaming
chunk / coalesce / break / humanDelay 互相影响最终效果
🛡
审批策略 (Approvals)
安全级别 + 转发策略 + 超时 → 需要分级选择 + 风险提示

📝 Tier 3 — Schema 自动表单

18+ 个配置域
独立字段、低频、低风险 → 自动生成即可，不值得手写 UI
🕐
时间 & 时区
userTimezone / timeFormat / envelopeTimezone — 独立字段，选一次不再动
📏
各种尺寸限制
mediaMaxMb / pdfMaxPages / imageMaxDimensionPx / bootstrapMaxChars — 纯数值
🔍
Memory & RAG
memorySearch 配置 — 低频，开关型
📋
Diagnostics & Logging
日志级别、路径 — 运维配置，首次设置
🔄
Update & CLI
更新渠道、banner — 设一次不再动
🌐
Discovery / Gateway 网络
mDNS、bind、TLS — 基础设施配置，纯表单足够
🎨
UI / Identity
seamColor / assistant name / avatar — 简单字符串 + 颜色选择器
📦
Context Pruning
mode / TTL — 两个字段，开关 + 数值

📊 总览对比

层级 UI 形态 配置域数 开发成本 维护成本 适合什么
Tier 1 专用交互组件（拖拽、规则编辑器、拓扑图） 6 高（每个 3-5 天） 中（上游变更需适配） 高频 + 可视化 + 强耦合
Tier 2 增强表单（分组 + 条件 + 说明 + 校验） 7 中（每个 1-2 天） 中 有耦合 + 需引导
Tier 3 Schema 自动表单（JSON Schema → Form） 18+ 低（一次性框架） 低（schema 变 UI 自动变） 独立 + 低频 + 低风险

💡 实施建议

第一步（覆盖 80% 场景）：先建 Tier 3 的 Schema 自动表单框架 → 立刻覆盖所有配置
第二步（提升体验）：为 Tier 2 配置域添加增强表单（分组 + 联动 + 说明）
第三步（差异化价值）：为 Tier 1 的 6 个高价值域构建专用交互 UI
原则：用 Tier 3 兜底所有配置 → Tier 2 覆盖重点 → Tier 1 打造亮点，优先级由下往上
