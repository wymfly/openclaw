🔄 主执行循环 src/agents/pi-embedded-runner/run.ts

EXECUTION PIPELINE
1
📋 初始化 & 配置解析
解析 AgentConfig → 确定模型(primary + fallbacks) → 加载 Skills → 构建系统提示 → 加载 Session 历史
agent-scope.ts system-prompt.ts skills-runtime.ts history.ts
resolveAgentConfig() → buildSystemPrompt() → loadSessionHistory()
↓
2
🔑 Auth Profile 选择
选择 API 密钥 profile → 检查 cooldown 状态 → 如果当前 key 被 rate-limited 则轮换到下一个
每个 profile 独立 cooldown 计时器，支持多个 provider 并行密钥池
Auth profile rotation with per-key cooldown tracking
↓
3
🧠 模型 API 调用 核心循环
发送 messages + tools 到 LLM Provider → 流式接收 response → 解析 content blocks
支持：text / tool_use / thinking blocks
最大重试次数：BASE 24 + 8/profile（最多 160 次）
runEmbeddedAttempt() → Pi SDK session.run()
↓ 响应分支
✅ 文本回复
→ 构建 payload（text + mediaUrl）
→ 发射 chat delta/final 事件
→ Block streaming 分块
→ 返回 EmbeddedPiRunResult
🔧 工具调用
→ 解析 tool_use block
→ 执行工具（可能需审批）
→ 工具结果 → 追加到 messages
→ 回到步骤 3（继续对话）
❌ 错误处理
→ context_overflow → 触发 Compaction
→ auth/billing → 模型 Fallback
→ rate_limit → Cooldown + 重试
→ abort → 终止运行
↓
4
🔧 工具执行循环 tool-use loop
模型返回 tool_use → 查找工具(Tool Catalog) → Policy Pipeline 检查(5层) → 需要审批？→ 执行 → 结果截断 → 追加到消息历史 → 回到模型调用
openclaw-tools.ts tool-policy-pipeline.ts exec-approval-manager.ts tool-result-truncation.ts
Tool → PolicyPipeline → ApprovalCheck → Execute → Truncate → AppendResult
↓
5
📦 上下文溢出处理 Compaction
token 数超过 reserveTokens 阈值 → 触发 compaction → 对历史消息做摘要压缩 → 保留最近消息 → 重试
模式：default（安全）safeguard（严格历史比例）
失败处理：compaction 失败 → 返回 error kind="compaction_failure"
compact.ts → reserveTokens / keepRecentTokens / maxHistoryShare
↓
6
📤 构建结果 & 投递
构建 EmbeddedPiRunResult → payloads (text/media) → meta (duration/tokens/stopReason) → 检查 messagingTool 发送记录 → 交付给 reply pipeline
EmbeddedPiRunResult { payloads, meta, didSendViaMessagingTool }

🏃 Run 模式（一次性）

• 执行完毕自动删除 Session
• 结果通过 announce 回传父 Agent
• 适合：独立子任务、数据处理
• 线程绑定：可选

💬 Session 模式（持久）

• Session 保留，可接收后续消息
• 绑定到会话线程
• 适合：长期对话、多轮交互
• 线程绑定：必需
