Design Decisions
  • DM Policy Radio Cards NEW — 不是简单的 select 下拉，而是带说明的卡片式单选。每个策略附带一句话解释 + recommended 标签。解决了"pairing vs open vs closed 是什么意思"的理解问题。
  • Retry Strategy Visualization NEW — 修改 retry 参数后，下方即时显示重试时序图（attempt → delay → retry → delay → ...）。让用户直观感受"3 次重试，基础延迟 1s"在时间轴上意味着什么。
  • Schema-driven fields — DM policy 和 retry 以外的字段从渠道的 JSON Schema 动态渲染（复用 ConfigPanel 的 SchemaForm），确保上游新增字段自动出现。
  • Per-channel schema adaptation — 不同渠道有不同的可配字段（Telegram 有 ipv4First, Discord 有 helloTimeout 等）。Settings tab 读取渠道特定的 schema section 渲染对应字段。
Data Flow
  • Read：调用 config.get 提取 channels.{channelId} section + config.schema 获取渠道 schema。
  • Write：通过 config.patch 写入 channels.{channelId}.{field}。
  • 渠道感知：根据 channelId 确定 schema 分支。Telegram/Discord/Slack/Feishu/WeCom 各有独立 schema（已在 Gateway 的 plugin schema composition 中定义）。
  • 无需新 Gateway RPC：复用 config.get + config.patch + config.schema。
Implementation Scope
  • 新增文件：ChannelSettingsTab.tsx（主组件）、DmPolicySelector.tsx、RetryStrategyEditor.tsx（含时序可视化）
  • 修改文件：ChannelDetail.tsx（注册新 tab）、channels store（扩展 fetchChannelConfig/saveChannelConfig）
  • 复用：SchemaForm（渲染 schema-driven 的 advanced 字段）、ConfigPanel 的 field 组件
