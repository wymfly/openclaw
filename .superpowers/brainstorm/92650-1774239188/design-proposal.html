2. 配置 Schema

# openclaw.yaml
agents:
  defaults:
    channels:
      eventStreams: ["chat", "lifecycle"]  # 全局默认: 最终文本 + 运行状态

  main:
    channels:
      eventStreams: ["chat"]  # 覆盖: 该 agent 的渠道只收最终文本

  debug-agent:
    channels:
      eventStreams: ["chat", "lifecycle", "tool", "thinking"]  # 调试 agent: 渠道收全量

解析优先级: agent.channels.eventStreams → agents.defaults.channels.eventStreams → ["chat", "lifecycle"] 硬编码默认
可选值: "chat" "lifecycle" "tool" "thinking"
与 verboseLevel 的关系: verboseLevel 继续控制 WS 侧 tool result 的载荷丰富度，eventStreams 控制渠道路由。两者独立。

5. 自洽闭环验证

场景 Gateway 发什么 客户端收什么 用户看什么
Deck 运维查看工具调用 全量（WS 全局广播） chat + tool + lifecycle + thinking ToolUseCard + BashResultView + RunStatusBar + ThinkingBlock
可用 BlockFilterBar 隐藏
WeCom 普通用户对话 按 eventStreams 过滤 chat + lifecycle（默认） "正在处理..." → 最终回复 → "处理完成"
WeCom 调试模式 eventStreams = 全量 chat + tool + lifecycle + thinking 完整工具日志（运维主动开启）
macOS App / CLI WS 定向（按 verbose） 不受 eventStreams 影响 取决于 verboseLevel 配置
✅ 自洽性
  • Gateway 侧: eventStreams 控制渠道路由（哪些 stream 到达渠道），verboseLevel 控制 WS 载荷（result 字段丰富度）— 两个独立维度
  • 客户端侧: Deck 用 BlockFilterBar 选择渲染，渠道无需客户端过滤（Gateway 已处理）
  • 配置层次: agent 级配置，Dashboard UI 可视化管理，运维一目了然
  • 上游解耦: 不修改 verboseLevel 逻辑，纯新增过滤层，rebase 友好
