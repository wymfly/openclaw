# Backend Gap Ledger

Baseline: `0f17c40ca7`, a descendant of shared baseline `341d965a36`

Use this ledger for Go backend/API/projection gaps discovered while restoring old Observe panel workflows. Gateway API remains the source of truth. Old Next Deck behavior is reference evidence only when the Gateway/source capability exists.

Status vocabulary:

- `covered-by-current-go`: current Go/API path exists; implementation should use it and cover shape with targeted tests.
- `needs-proof`: old workflow may need fields or behavior not yet proven in Go/Gateway; no backend edit until a targeted test or payload inspection proves the gap.
- `go-adapter-missing-but-upstream-exists`: Gateway/source supports the workflow, but Go adapter/API projection is missing; backend/API work is allowed.
- `gateway-unsupported`: source capability is absent; render an explicit unavailable state instead of fabricating data.

Panel-local UI edits may proceed while a row is `needs-proof`, but they must use existing APIs and render explicit unavailable states for unproven capability. `needs-proof` blocks only Go/API adapter edits.
