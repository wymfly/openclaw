## Why

`api-explorer` is the first blocking/failing-evidence module after the Agents
sample. The shared gate repaired its stale Gateway method-count assertion, but
the module still has only mock functional evidence unless it receives a
prototype-current comparison, structured visual verdict, and bounded real
Gateway evidence.

The panel is also a contract-chain inspection surface. Its product quality
depends on faithfully adapting `gateway.describe` and typed BFF invocation
contracts rather than hardcoding a static catalog.

## What Changes

- Identify `deck-go/frontend-handoff/modules/api-explorer/prototype.html` as the
  active visual target and treat `prototype-v1-codex.html` as historical
  context.
- Reconcile prototype assumptions with the current Gateway describe/invoke
  contract chain.
- Fix deterministic API Explorer UI, fixture, API facade, contract, or backend
  drift discovered during the parity pass.
- Produce strict mock prototype parity evidence for the ready workspace state:
  prototype screenshot, mock-current screenshot, side-by-side contact sheet,
  structured verdict, and accepted-exception ledger if differences remain.
- Attempt bounded real Gateway evidence for describe, method selection, and a
  safe typed invocation path.
- Update the remediation matrix, API Explorer handoff notes, and head task
  status.
