## Why

The current Skills panel inherited from archived `frontend-skills-hifi-contract-redesign`, `frontend-skills-real-contract-verification`, and `deck-go-skills-plugins-contract-completion` is a high-fidelity production implementation: full Gateway RPC wrappers (`fetchSkills / updateSkill / installSkill / fetchSkillHubBins / fetchSkillHubDetail / installSkillHub / updateSkillHub / fetchAgentSkills / updateAgentSkills`), a typed Go BFF surface, and a 1485-line three-tab UI (`SkillHubTab / SkillInfoTab / SkillMatrixTab`). It is wired but not productized as a control plane:

- Mutation paths are all marked `mutation-isolation-blocked` in the existing implementation notes; install / update / agent-matrix writes have never been verified against a real Gateway.
- Skills currently exposes a **two-way agent×skill matrix edit path** through `SkillMatrixTab.onToggle` -> `updateAgentSkills` -> `deck.agents.skills.set`. This collides with the codex agents D6 boundary that says per-agent skill assignment belongs to Agents, and creates two competing write paths for the same `agents.list[].skills` config domain.
- The Deck-facing `DeckGoSkillEntry` lacks product semantics: there is no `apiKeyConfigured`, no explicit raw/product source taxonomy, no `agentUsage`, no `availableActions`, no `unsupportedReasons`, and no `owningPlugin`. The DTO also passes `config` through unchanged in the BFF map fallback path, so a saved `config.apiKey` value can leak into responses if not sanitized at the Deck boundary. Gateway does not currently expose ClawHub tracking/version status in `skills.status`, so per-skill installed-version / update-available semantics are not part of this pass.
- The IA is a three-tab engineering surface, not a control plane. The codex `deck-go-agents-product-control-plane` proposal locks `list workbench + detail hero + section nav` as the unified product-control IA; Skills should match that range so users moving between Agents and Skills do not encounter two different rhythms.
- Mutation safety is undifferentiated: enable/disable is an inline toggle without an "X agents in use" affordance; `SkillConfig` mixes apiKey password input and raw JSON env textarea without a clear secret model; install combines `SkillHubTab` search and `InstallSkillDialog` per-bin pick into an ad-hoc multi-surface flow.
- Gateway has no `skills.uninstall` RPC, but the UI does not say so. Operators expect a delete affordance for skills they own; today there is neither a button nor an explanation, which is worse than an honest handoff banner.

## What Changes

- Redesign Skills as a product control plane around installed-skill identity, source & activation, secret posture, eligibility health, agent usage, and owning-plugin relationship. The mental model is admin + power-user mixed (catalog browse + installed management + global read-only matrix), with **all editing of `agents.list[].skills` removed from Skills and consolidated into Agents (codex `deck-go-agents-product-control-plane` D6).**
- Replace the three-tab IA with a list workbench plus detail hero and product sections: `Identity / Source & activation / API key / env / Eligibility health / Agent usage (read-only matrix slice) / Owning plugin link / Danger zone`.
- Remove the agent-matrix write path from Skills. `SkillMatrixTab.onToggle` and `updateAgentSkills` calls inside Skills components MUST be deleted; the `updateAgentSkills` wrapper in `frontend-new/src/api.ts` MUST stay for Agents to keep using. This is an explicit breaking removal that ships in this change.
- Replace `SkillHubTab` with a five-step `InstallSkillWizard` (source -> slug & version preview -> apiKey optional -> env optional -> review and confirm). Because the Gateway `skills.install` clawhub branch only accepts `source/slug/version/force/timeoutMs`, the wizard captures apiKey and env locally and writes them through a post-install chained call to `updateSkill(skillKey, {apiKey?, env?})` after `installSkillHub` succeeds; the chain only fires if either field was provided. Rename the existing `InstallSkillDialog` to `AddBinDialog` and keep it as a per-skill secondary flow for running a selected install recipe (`brew/node/go/uv/download`) declared by a loaded skill, not for installing a local-directory skill itself.
- Extend `SkillConfig` into a compliant secret edition: keep the masked password input, add an `apiKeyConfigured` badge, add a `Clear` action, and replace the raw JSON env textarea with a key-value table. Do not show a last-4 hint in this pass because current Gateway read APIs do not expose a safe apiKey summary; mark `Rotate` as deferred follow-up because Gateway has no rotate RPC and do not simulate rotate as `clear + update`.
- Add a four-level mutation safety model:
  - L0 normal: `enable / disable` inline toggle with live "X agents in use" hint.
  - L1 guarded impact: `update env` and a global `update all ClawHub-managed skills to latest` operation via guarded drawer with affected-agent count and explicit scope. Per-skill update-available buttons are intentionally not exposed because current `skills.status` does not expose ClawHub origin slug or installedVersion; a future `gateway-skills-tracking-status-contract` proposal stub records this gap. Version selection on update is also intentionally not exposed because the Gateway `skills.update` clawhub branch only accepts `{source, slug, all}` (no `version`); a future `gateway-skills-update-version-contract` proposal stub records that separate gap.
  - L2 guarded secret: `update apiKey` and `clear apiKey` via dedicated dialog, no plaintext display, configured/not-configured state only.
  - L3 setup wizard: `install` via the new five-step wizard, with a final review step that previews the openclaw.json mutation and predicts impact.
- Treat `uninstall` as an explicit unsupported-needs-contract handoff. `DeckGoSkillEntry.unsupportedReasons.uninstall = "gateway-rpc-missing"` MUST surface as a banner in the detail Danger zone instead of a destructive button. Document `gateway-skills-uninstall-contract` as a future change stub.
- Extend Deck-facing DTOs only with derivable product fields and never expose secret values: `apiKeyConfigured: boolean`, `sourceRaw: string`, product `source: 'bundled'|'managed'|'workspace'|'extra'|'personal'|'project'|'unknown'`, `agentUsage: { count, agentIds[] }`, `availableActions: ('enable'|'disable'|'updateApiKey'|'clearApiKey'|'updateEnv'|'installClawHub'|'runInstallRecipe'|'updateAllClawHub')[]`, `unsupportedReasons: { uninstall?: string; rotate?: string; perSkillUpgrade?: string; apiKeyHint?: string }`, and a best-effort `owningPlugin?: { id?, name? }` derived by joining `deck.plugins.list` capabilities/tool names/provider ids. Where the join cannot resolve, the field is `null` and the UI explicitly says "unknown plugin"; precise plugin-to-skill mapping is recorded as a separate follow-up. The Deck DTO MUST sanitize the existing `config` map to omit any saved `apiKey` value (and any field listed in a known-secret keylist) on both the typed and the map fallback BFF normalization paths; `config` becomes a `Record<string, unknown>` with secret keys removed at the Deck boundary, so apiKey plaintext never leaves the Go BFF.
- Add a real-Gateway verification model with a three-tier fallback so the change can close honestly under any of the realistic environments:
  - L1 (preferred): isolated config root + a preconfigured ClawHub staging fixture slug (e.g. `clawhub-staging-fixture-<env>`) that already exists on the ClawHub side, paired with run-id-scoped local artifacts (dummy `__deck_test_apikey_<runId>` value, run-id-tagged env keys) for install, enable, disable, update env, update apiKey, clear apiKey, and global update-all-to-latest. ClawHub does not expose a publish RPC, so the slug itself MUST be staged out of band; cleanup MUST refuse non-staging targets and SHOULD restore the fixture to its pre-run state.
  - L2 (degraded): when no staging slug is available, ClawHub network is unreachable, or disk write is unsafe, mark mutation evidence `skipped-safe` per `frontend-new/CLAUDE.md` rule for installed-skill resources, and prove read paths plus UI write protections (DOM never contains saved apiKey; no Skills component invokes `updateAgentSkills`; no Skills component invokes `skills.uninstall`) instead.
  - L3 (floor): mock-only mutation evidence with read paths and negative invalid-param coverage on real Gateway, including the Deck typed BFF rejection of methods outside the typed allowlist.
- Anchor cross-module navigation rather than duplicate editors: the toolbar shows `Approvals: N pending` derived from `plugin.approval.list` and links to the Approvals panel; the detail Owning Plugin section links to the Plugins panel; the Agent Usage section links to the per-agent detail in Agents.
- Calibrate visual authority to OpenSpec product blueprint plus `frontend-new` design system; the existing `frontend-handoff/modules/skills/prototype.html` is density and rhythm reference only and is explicitly stale relative to this product blueprint.
- Add focused tests, mock visual states, and bounded real verification covering the four-level mutation safety model, the breaking removal of agent-matrix write, the wizard, the secret model, the unknown-plugin degradation, and the uninstall handoff banner.

## Capabilities

### New Capabilities

- `deck-go-skills-product-control-plane`: product-level Skills control-plane behavior, cross-module ownership boundaries, four-level mutation safety, install wizard semantics, secret boundary, uninstall handoff, three-tier real verification fallback, and verification evidence.

### Modified Capabilities

- None. Existing skills hifi, real-contract verification, and skills/plugins contract-completion specs remain valid baselines; this change layers a stricter product-control capability on top.

### Removed Behaviors

- Skills module no longer exposes a write path for `agents.list[].skills` (`updateAgentSkills` invocation from `SkillMatrixTab.onToggle`). Agents module owns the write path via codex `deck-go-agents-product-control-plane` D6. The `updateAgentSkills` wrapper itself is preserved for Agents.

## Impact

- **Gateway truth (no schema change in this pass)**: `src/gateway/server-methods/skills.ts`, `src/gateway/server-methods/skills-method-defs.ts`, `src/gateway/server-methods/deck/agents-skills.ts`, `src/gateway/protocol/schema/agents-models-skills.ts`. Verified RPC list: `skills.search / skills.detail / skills.bins / skills.status / skills.install / skills.update / deck.agents.skills.get / deck.agents.skills.set / deck.plugins.list / plugin.approval.list`. Confirmed missing: `skills.uninstall`, `skills.rotate-apikey`, and a safe read RPC for per-skill ClawHub tracking/version/origin status.
- **Contracts**: `deck-go/contracts/source/deck-api.contract.ts` extends `DeckGoSkillEntry` with the derived product fields and adds `DeckGoSkillAvailableActions / DeckGoSkillAgentUsage / DeckGoSkillUnsupportedReasons / DeckGoSkillOwningPluginRef / DeckGoSkillProductSource`. It does NOT add `installedVersion`, `availableVersion`, `apiKeyHintLast4`, or `DeckGoSkillUpdateState` in this pass because those cannot be derived from current Gateway read contracts without leaking secrets or reading Gateway-private ClawHub origin files. The detail surface is rendered from list entries: no separate `DeckGoSkillDetailResponse` is added in this pass and no `GET /skills/{skillKey}` route is introduced, since the existing list response already carries every field the detail hero needs.
- **Go BFF/runtime**: `deck-go/backend/internal/server/inventory.go` `normalizeSkillsResponse` (and the `deckSkillEntryFromMap` map fallback) add owningPlugin best-effort join, `agentUsage` join via agent skill filters, product source normalization from raw OpenClaw source strings, `apiKeyConfigured` derivation from safe redacted config/status evidence without exposing the saved value, and explicit `config` secret sanitization (omit `apiKey` and known secret env names from the response on both the typed and the map paths). `legacy_inventory.go` and `contract_adapters.go` may also need adjustment depending on how the existing normalization is layered. Per-skill ClawHub version/update availability stays an explicit unsupported reason until Gateway exposes tracking status.
- **Frontend**: rewrite `deck-go/frontend-new/src/components/panels/skills/SkillsPanel.tsx`; delete `SkillHubTab.tsx`, `SkillMatrixTab.tsx`, and `SkillInfoTab.tsx`; rename `InstallSkillDialog.tsx` to `AddBinDialog.tsx`; introduce `InstallSkillWizard.tsx`, `SkillDetailHero.tsx`, `SkillSections.tsx` (or split into per-section components), `SkillSecretDialog.tsx`, `SkillEnvKeyValueEditor.tsx`, `SkillUninstallHandoffBanner.tsx`, `SkillUpdateAllClawHubDrawer.tsx`, and a read-only `SkillAgentUsageSection.tsx`; extend `SkillConfig.tsx` (or fold it into `SkillSecretDialog.tsx`); extend `SkillList.tsx` for filter and selection; update `skill-model.ts` to carry the new derived fields; update `i18n` strings.
- **Tests**: rewrite `SkillsPanel.test.tsx` to drop matrix toggle assertions and add wizard / secret / uninstall handoff / agent-usage read-only / breaking-removal assertions.
- **E2E and evidence**: extend `deck-go/test/e2e/skills-visual.spec.ts` with the new product states; extend or add `deck-go/test/e2e/skills-real-gateway.spec.ts` with three-tier fallback; update `deck-go/frontend-handoff/modules/skills/implementation-notes.md` with a product-control-plane closeout.
- **Dependencies**: no new runtime dependency. Any new list/virtual-scroll or form library decision must be raised separately if existing `frontend-new` atoms and patterns are insufficient.
