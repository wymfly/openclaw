# Skill 摘要（由 orchestrator 从完整 Skill 和 CLAUDE.md 提取）

## 项目级质量约束（来自 CLAUDE.md，Codex 不可见，必须遵守）

- TypeScript checks: `pnpm tsgo` — 每次修改后运行，修复全部类型错误再 commit
- Lint/format: `pnpm check` — 提交前必须通过
- Tests: `pnpm test` (vitest) — 提交前运行完整测试套件
- 避免 `any` 类型；不添加 `@ts-nocheck`
- mock 对象必须包含所有必填字段（尤其时间戳字段）
- mock patch 路径 = 消费方的 import 路径（不是定义方的路径）
- 使用 `scripts/committer "<msg>" <file...>` 提交（不要手动 git add/commit）
- commit 消息格式：`[enhanced][codex-impl] <type>(deck): <description>`
- 不要添加不必要的 docstrings/comments/type annotations 到未修改的代码
- 保持文件简洁，under ~700 LOC

## Dashboard 特定约束（来自 dashboard/CLAUDE.md）

- 新增 Gateway RPC 方法必须同步 allowlist（本项目不新增 RPC，无需操作）
- `tsc --noEmit` 零错误后才能标记任务完成

## TDD 关键约束（纪律型 — Phase 3 全程生效）

- NO PRODUCTION CODE WITHOUT A FAILING TEST FIRST
- Red-Green-Refactor 三步不可跳步：先写失败测试 → 写最小实现 → 重构
- 每个测试验证一个行为
- 测试名称描述被测行为（"returns null when..."，"clears only targeted..."）
- 使用 `describe` 块按功能组织测试
- mock 只在真正需要隔离时使用（本项目用 in-memory SQLite，优先真实 DB 测试）
- 每个 task 完成后运行 `pnpm test -- <相关测试文件>` 验证
- 测试需清理 timers/env/globals/mocks

## SQLite 特定注意事项

- `Database.transaction()` 使用 BEGIN/COMMIT/ROLLBACK 包裹回调（见 `dashboard/server/db.ts:148`）
- 事务内所有操作是同步的（sql.js 是同步 API）
- 测试使用 `openDb(":memory:")` 创建 fresh in-memory database（见现有测试模式）
- 每个测试 `beforeEach` 创建新 db + store，`afterEach` close
