# 多模态管线功能测试计划

## 测试环境前置条件

- Gateway 已启动且状态为"已连接"
- Dashboard dev server 运行在 localhost:3000
- 至少一个 Agent 配置了支持 vision 的模型（如 `anthropic/claude-sonnet-4`）
- 至少一个 Agent 配置了不支持 vision 的模型（如纯文本模型）
- WeCom 渠道已配置（WeCom 相关测试用）

## 测试文件准备

| 文件               | 用途            | 创建方式                 |
| ------------------ | --------------- | ------------------------ |
| `test-image.png`   | 图片上传测试    | 任意 PNG 图片 (< 5MB)    |
| `test-doc.txt`     | 文本文件测试    | 纯文本文件               |
| `test-large.bin`   | 超限文件测试    | 6MB 随机二进制文件       |
| `test-log.log`     | 文本启发式测试  | 文本内容但扩展名为 .log  |
| `test-data.csv`    | CSV 文件测试    | 几行 CSV 数据            |
| `test-report.pdf`  | PDF 测试        | 任意 PDF (< 5MB, 含文字) |
| `test-binary.xlsx` | Office 文件测试 | 任意 Excel 文件          |

## C. 多模态管线（Gateway 核心）

### C1. 文件到达 Agent

- [ ] **C1.1** 发送图片 → 图片保存到 `~/.openclaw/media/inbound/` 目录
- [ ] **C1.2** 发送图片 → Agent 能"看到"图片内容（vision 模型描述图片）
- [ ] **C1.3** 发送 PDF → Agent 能读取 PDF 文本内容（回复中引用 PDF 内容）
- [ ] **C1.4** 发送 .txt 文件 → Agent 能读取文件内容

### C2. 文本启发式检测

- [ ] **C2.1** 发送 .log 文件（MIME 为 application/octet-stream）→ Agent 能读取内容（启发式识别为文本）
- [ ] **C2.2** 发送 .xlsx 文件 → 不会被误判为文本（二进制特征 >> 2%）

### C3. 错误通知

- [ ] **C3.1** 发送 > 5MB 文件（如果绕过前端校验）→ 聊天中显示"⚠️ 媒体处理: xxx — 文件太大"

### C4. Vision 模型警告

- [ ] **C4.1** 给不支持 vision 的 Agent 发送图片 → 聊天中显示"当前模型不支持图片分析"提示
- [ ] **C4.2** 给支持 vision 的 Agent 发送图片 → 无警告，正常分析图片

### C5. 附件存盘时序

- [ ] **C5.1** 重复发送（幂等键相同）→ 不产生重复文件（dedupe 在存盘前）

### H2. 特殊文件名

- [ ] **H2.1** 文件名含中文 → 正常显示

- [ ] **H2.3** 文件名含特殊字符 `<>&"` → 不破坏消息格式（XML 转义）

- [ ] **H3.1** Artifact iframe 无法访问主页面 DOM（sandbox 限制）
- [ ] **H3.2** Artifact iframe 无法导航到主页面（无 allow-top-navigation）
- [ ] **H3.3** Artifact iframe 可以执行 JavaScript（allow-scripts）

### H4. 并发与竞态

- [ ] **H4.1** 快速连续发送两条消息 → 两条都正确处理，不混淆
- [ ] **H4.2** 发送消息后立即切换会话 → 不崩溃
- [ ] **H4.3** 流式回复中上传文件 → 上传被阻止（isStreaming 守卫）
