Subagent Lifecycle Sequence

Spawn → execute → steer/kill → announce → cleanup 
sequenceDiagram
    participant P as Parent Agent
    participant GW as Gateway
    participant REG as Subagent Registry
    participant C as Child Agent
    participant AI as AI Provider

    Note over P: Agent calls sessions_spawn tool

    P->>GW: spawnSubagentDirect(task, agentId, model)
    activate GW

    Note over GW: Validate 5 gates:
1. Agent ID format
2. Spawn depth < max(3)
3. Active children < max(5)
4. Cross-agent allowlist
5. Sandbox compatibility

    GW->>REG: Register SubagentRunRecord
    REG-->>GW: runId + childSessionKey

    GW->>C: gateway.agent(task, childSessionKey)
    deactivate GW
    activate C

    GW-->>P: SpawnSubagentResult(accepted, runId)
    Note over P: Parent continues execution
(no polling needed)

    C->>AI: Model inference
    activate AI
    AI-->>C: Streaming response
    deactivate AI

    Note over C: Tool calls + execution loop

    alt Parent steers child
        P->>GW: subagents steer(target, newMessage)
        activate GW
        GW->>C: Abort signal
        Note over C: Current run interrupted
        GW->>C: Re-inject with new message
        deactivate GW
        C->>AI: New inference with steered message
        activate AI
        AI-->>C: New response
        deactivate AI
    end

    alt Parent kills child
        P->>GW: subagents kill(target)
        activate GW
        GW->>C: Abort signal + clear queues
        Note over C: Terminated
        GW->>REG: markTerminated(killed)
        deactivate GW
        deactivate C
    else Child completes normally
        C->>REG: Mark outcome(ok, resultText)
        deactivate C

        REG->>GW: Announce result to parent
        activate GW
        GW->>P: System event with child result
        Note over P: Parent receives result
and continues
        deactivate GW

        alt mode = run
            REG->>REG: Delete child session
            Note over REG: .jsonl file removed
        else mode = session
            Note over REG: Session kept
Thread follow-ups enabled
        end
    end

Parent spawns child via sessions_spawn tool. Gateway validates 5 gates, registers run, and dispatches. Child executes independently. Parent can steer (interrupt + redirect) or kill (cascade abort). On completion, result is auto-pushed to parent as a system event. Run-mode sessions are auto-deleted; session-mode sessions persist for thread follow-ups.
