Channel Message Flow

End-to-end: inbound message to outbound delivery

    participant User as User
    participant CH as Channel Plugin

    User->>CH: Send message
    activate CH

    Note over CH: Signature verify
AES decrypt
Dedup (msgid, 10min TTL)

    CH->>GW: dispatchChannelMessage()
    deactivate CH
    activate GW

    GW->>RT: dispatchInboundMessage()
    activate RT

    RT->>SS: Load session entry
    SS-->>RT: SessionEntry (model, auth overrides)

    Note over RT: Parse session key
agent:id:channel:rest
Check send policy

    RT->>AG: getReplyFromConfig()
    activate AG

    Note over AG: Resolve agent config
Build skill snapshot
Apply tool policies
Select model (cascade)

    AG->>AI: Model inference
    activate AI
    AI-->>AG: Streaming response
    deactivate AI

    AG->>RD: Tool Results
    activate RD
    AG->>RD: Block Replies (streaming)
    AG->>RD: Final Reply
    deactivate AG

    Note over RD: Three-stage ordering:
tool → block → final
Human delay (800-2500ms)

    RD->>OB: Deliver payload
    activate OB

    Note over OB: Text chunking
Media attachment
Cross-channel routing

    OB->>CH: sendText() / sendMedia()
    activate CH
    CH->>User: Deliver response
    deactivate CH
    deactivate OB

    RD->>SS: Update session state
    deactivate RD
    deactivate RT
    deactivate GW

Complete message lifecycle: User sends via any channel plugin. Plugin verifies, decrypts, and deduplicates. Gateway routes via session key to the resolved agent. Agent runs model inference with tools and skills. Reply Dispatcher enforces strict three-stage ordering (tool results, block replies, final reply). Outbound delivery chunks text and sends back through the channel plugin.
