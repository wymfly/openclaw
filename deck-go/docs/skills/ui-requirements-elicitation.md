# Skill: UI Requirements Elicitation (Socratic)

> **何时启用**：用户（特别是非设计/前端背景的产品/工程负责人）说"做一个 X 页面/模块"，但描述较模糊，凭直接发挥很可能做不到位。
>
> **目标**：用 3-5 轮**对比式提问**（而不是开放式提问）把用户脑子里模糊的"感觉"翻译成可执行的 UI 需求，让第一稿就 80% 对味。

---

## 核心方法论

### 为什么传统提问方式失败

非设计背景的用户**没有词汇库**来描述 UI。问他们：

- "你想要什么样的视觉风格？"——他们答不出
- "信息密度怎么样？"——他们听不懂
- "用什么交互模式？"——他们不知道有哪些选项

这些问题对设计师有意义，对用户是天书。

### 取代方案：让用户做选择题

把所有问题转成**对比式**：

| ❌ 抽象问        | ✅ 对比问                                                              |
| ---------------- | ---------------------------------------------------------------------- |
| "想要什么风格？" | "更像 Linear（紧凑、暗色、工程感）还是 Notion（留白、浅色、文档感）？" |
| "信息密度多大？" | "首屏想看到 5 条信息还是 50 条？"                                      |
| "什么交互模式？" | "用户主要是浏览数据，还是频繁操作（增删改）？"                         |
| "要什么动效？"   | "动效像 Apple（克制、200ms 内）还是像游戏（弹跳、有戏剧性）？"         |

**原则**：让用户**指认**而不是**描述**。指认是认知低成本，描述是高成本。

---

## 提问框架：5 个维度

按这个顺序问，每个维度 1-3 个问题。**不要一次问完**——分轮次，每轮 2-4 个问题，让用户消化。

### 维度 1：参考锚点（最重要，先问）

> "你心里有 1-2 个'我希望它像 X'的产品吗？哪怕只是某个局部很像？"

如果用户答不出，给候选列表（按场景）：

**工具/效率类**：Linear、Things、Cron、Raycast、Superhuman、Arc Browser
**协作/文档类**：Notion、Figma、Pitch、Coda、Craft
**数据/Dashboard 类**：Stripe、Vercel、Posthog、Mercury、Plaid
**消费/内容类**：Cash App、Headspace、Apple Music、Bear、Things

让用户选 1-3 个，**或者**告诉你"都不像"+"我希望像 \_\_\_"。

> 💡 这一步获得的信息量 > 后面所有维度。如果用户能给出明确锚点，后面 4 个维度的工作量减半。

### 维度 2：视觉气质

每条都是二选一/三选一对比。一次问 3-4 条：

| 问题     | 对比                                                                                       |
| -------- | ------------------------------------------------------------------------------------------ |
| **明暗** | 暗色（Linear、Vercel）/ 浅色（Notion、Stripe）/ 自动跟随系统                               |
| **密度** | 紧凑（Bloomberg、Linear，信息高度密集）/ 中等（Stripe）/ 宽松（Apple，留白多）             |
| **风格** | 几何 sans（Inter、Geist 那种）/ 人文 sans（带温度，如 Söhne）/ 衬线（编辑感，如 New York） |
| **色彩** | 单色调 + 1 个强调色（Linear 紫）/ 中性灰白 + 多色 status（Stripe）/ 彩色丰富（Notion）     |
| **圆角** | 锐利（0-2px，Vercel）/ 中等（4-8px，主流）/ 圆润（12px+，iOS 感）                          |
| **质感** | 完全平面（无阴影、无渐变）/ 微立体（subtle shadow）/ 有质感（玻璃态、渐变）                |

> 💡 给每个选项配一句"为什么选它"，帮用户判断。例："紧凑适合数据密集的工具页，宽松适合低频但重要的页面"。

### 维度 3：信息密度与布局

> "用户进到这个页面，**首屏**应该看到多少东西？"

给 4 个档位让用户选：

- **L1 单焦点**：1-2 个核心元素 + 大留白（如 Apple Music 当前播放页）
- **L2 卡片网格**：3-12 张卡片（如 Notion 模板库）
- **L3 列表/表格**：20-50 行（如 Linear issue 列表）
- **L4 数据墙**：50+ 信息单元（如 Bloomberg、Plaid Dashboard）

接着问布局结构：

- 单栏 / 双栏（左侧栏 + 主内容）/ 三栏（侧栏 + 主 + 详情）？
- 有没有需要常驻的元素？（顶栏、底部 dock、悬浮按钮）

### 维度 4：交互模式

最关键的两条：

> **Q1：用户主要在这个页面"做什么"？**
>
> - 浏览（看为主，偶尔操作）
> - 操作（增删改查频繁）
> - 输入（表单/编辑器为主）
> - 命令（搜索 / 快捷操作 / 命令面板）

> **Q2：键盘党还是鼠标党？**
>
> - 强键盘（Linear、Superhuman、Raycast——每个动作都有 hotkey，⌘K 命令面板是核心）
> - 平衡（大部分用鼠标，重要动作有 hotkey）
> - 纯鼠标（消费级产品，用户不期望学键盘）

可选追问：

- 多选 / 批量操作要不要？
- 拖拽要不要？
- 实时协作要不要（多光标 / presence）？
- 有没有"撤销/重做"刚需？

### 维度 5：状态与边界

非设计用户最容易忽略的部分。**Claude 必须主动问**：

> "我会处理这些状态，每个都跟我说一句'要不要 / 怎么处理'：
>
> 1. **空状态**：第一次进来什么都没有，给 onboarding 引导 / 给示例数据 / 直接空白？
> 2. **加载中**：骨架屏 / spinner / 进度条 / 不显示？
> 3. **错误**：toast 提示 / 行内错误 / 全页错误页？
> 4. **成功反馈**：toast / 行内 checkmark / 不反馈（静默）？
> 5. **极端数据**：如果列表有 10000 条会怎样？如果某个字段超长会怎样？
> 6. **离线 / 网络慢**：要不要离线提示？要不要 optimistic update？"

> 💡 这一步往往会让用户意识到"我没想过这些"——这是 skill 价值的最大体现。

## 提问的节奏控制

**严禁一次性把 30 个问题甩给用户**——会被劝退。

正确节奏：

```
第 1 轮（开场，2-3 问）
  └─ 参考锚点 + 一两条关键气质问题
       ↓ 用户回答
第 2 轮（视觉气质，3-4 问）
  └─ 明暗 / 密度 / 圆角 / 色彩
       ↓
第 3 轮（信息 + 交互，3-4 问）
  └─ 信息密度 + 主任务 + 键盘/鼠标
       ↓
第 4 轮（状态与边界，列表式过一遍）
  └─ 空/loading/错误/极端值
       ↓
（可选）第 5 轮：拿不准的细节追问
       ↓
开始设计
```

**每轮间隔，让用户消化**。Claude 不要在一轮里塞超过 5 个问题。

## 用 questions_v2 工具的格式

用本工具自带的 `questions_v2` 来出题，有几个好处：

- 渲染成原生组件（radio / checkbox / svg-options），用户点击选择
- 比纯文字提问更友好
- 视觉对比题用 `svg-options` 渲染缩略示意图

### 视觉气质类问题：用 svg-options

例如"圆角偏好"：用 4 个 SVG 各画一个矩形，圆角 0/4/12/24px 对比。
例如"明暗偏好"：用 SVG 画两个 mock 卡片，深色和浅色对比。

### 参考锚点类问题：用 text-options multi

```
title: "选 1-3 个你心里的设计参考"
multi: true
options: [
  "Linear（紧凑、暗色、工程感）",
  "Notion（留白、浅色、文档感）",
  "Stripe（克制、专业、文档+表单）",
  "Vercel（黑白、几何、极简）",
  "Raycast（命令面板、键盘党）",
  "Things（极简、宽松、轻交互）",
  "都不像",
  "Other"
]
```

### 信息密度：text-options 单选 + 文字描述

```
title: "首屏信息密度"
options: [
  "单焦点（1-2 个核心元素，大量留白）",
  "卡片网格（3-12 张卡片）",
  "列表 / 表格（20-50 行）",
  "数据墙（50+ 信息单元）",
  "Decide for me",
  "Other"
]
```

## 提问后的输出：写一份"设计 brief"

提问结束后，**不要立即开始画**。先写一份 1 页的 design brief 让用户确认：

```markdown
## [模块名] 设计 brief

**参考锚点**：Linear + 一点 Notion 的留白感

**视觉气质**：

- 暗色为主，浅色作为可选
- 紧凑密度（信息高度密集）
- 几何 sans（Inter / Geist 风格）
- 单色 + 1 个紫色强调
- 4px 圆角
- 平面 + 微 shadow

**信息架构**：

- 三栏布局：侧栏导航 + 主列表 + 详情面板
- 首屏 30+ 条 issue
- 顶部固定筛选栏

**核心交互**：

- 强键盘：⌘K 命令面板、j/k 上下、enter 进入、e 编辑
- 多选 + 批量操作（shift+click）
- 拖拽改优先级

**状态处理**：

- 空：onboarding 引导（创建第一个 issue）
- 加载：骨架屏
- 错误：toast + 行内
- 成功：静默 + subtle 动效

**边界**：

- 列表分页（每页 50）
- 长字段截断 + tooltip
- 离线显示 banner，操作进入队列
```

用户确认后再动手。这个 brief 也可以存到 `docs/design-briefs/<module>.md` 当未来参考。

## 一个完整的对话范例

**用户**："帮我设计 deck list 页面"

**Claude（应用本 skill）**：

> 在动手之前，我想确保第一稿就接近你想要的样子。先问两个最重要的问题：
>
> [questions_v2 弹出]
>
> 1. 你心里有没有 1-3 个"我希望 deck list 像 X"的产品？（多选）
>    - Linear（issue 列表那种）
>    - Notion（页面侧栏那种）
>    - Pitch（演示工具的 deck 列表）
>    - Figma（文件库那种）
>    - Apple Keynote
>    - 都不像 / Other
> 2. 这个列表用户**主要做什么**？
>    - 浏览找东西（搜索 + 翻看为主）
>    - 频繁操作（创建/重命名/删除/移动很多）
>    - 协作（看谁改了什么、谁在编辑）
>    - 演示前快速进入（一键打开演讲模式）

用户回答后，进入第 2 轮（视觉气质），第 3 轮（密度+交互），第 4 轮（状态），最后产出 brief，确认后开始画。

## 反模式

- ❌ **用户一句话需求就开干**——产出大概率不对味
- ❌ **一次甩 20 个问题**——用户被劝退
- ❌ **问"想要什么风格"这种开放问题**——用户答不出
- ❌ **跳过参考锚点这一步**——后面所有维度都失去校准
- ❌ **跳过状态与边界**——做出来的页面只有 happy path
- ❌ **拿到答案不写 brief 直接开干**——用户和 Claude 的理解可能仍有出入
- ❌ **brief 写得像设计文档**——用户看不懂，要用大白话

---

## 适用场景与不适用场景

### 适用 ✅

- 新模块设计（用户知道功能，但不知道 UI 长什么样）
- 重构现有页面（要换风格 / 优化体验）
- 多方案对比之前（先用 brief 锁定方向）

### 不适用 ❌

- 微调（比如"把这个按钮改成蓝色"）——不需要 brief
- 用户已经给了详细 spec / 截图——直接做
- 探索性 wireframe——用 wireframe skill 而不是这个

---

## 一句话总结

**让用户做选择题，不让用户做问答题。** 5 个维度 × 对比式提问 × 分轮节奏 × 输出 brief 确认 = 第一稿就 80% 对味。
