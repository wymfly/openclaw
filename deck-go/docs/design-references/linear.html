§ 03

组件样本

每个组件都为"高频快速操作"服务：紧凑、键盘标注、状态用色彩点位编码。

Buttons · 紧凑 + 键盘提示

主按钮永远配 single-key 快捷键，因为这是键盘党的家。padding 比 Claude.ai 小一半（5px vs 9px），密度优先。

Input · 双状态

Issue title…
Streaming hangs after long tool calls

未聚焦完全融入背景，聚焦时浮一层 + indigo 描边 + 2px 软光晕（比 Claude.ai 的 3px 更紧）。

Status · 信息点位编码

Todo In Progress Done Blocked Canceled

Linear 标志做法：用形状（圆/扇形/对勾/感叹号/斜杠）配色块编码状态，扫一眼就能识别 5 种状态。

Priority Bars · 等级条形图

Urgent High Medium Low

14×14 像素的等级条形图，把"优先级"做成可视化柱状。比文字 "P0/P1/P2" 扫得快得多。

§ 04

灵魂细节

这些是 Linear 让人一眼认出的特征。视觉好抄，工程哲学难抄。

⌘K

命令面板是"真正的主菜单"

不是花哨功能。所有动作都能在 ⌘K 完成——创建、搜索、跳转、设置、切换。这让用户可以从不碰鼠标。

⚡

本地优先 + Optimistic Update

所有操作几乎瞬间生效（不等服务器）。这种"丝滑感"不是 CSS 动效，是底层架构：本地 SQLite + 后台 sync。

▦

密度即美

32px 行高、4px spacing 节奏、不留多余空白。每屏装下 30+ issue。Linear 把"信息密度"做成了审美主张，而不是工程妥协。

●

状态用形状编码

Todo（空圆）/ Progress（扇形）/ Done（实心+对勾）/ Blocked（!）/ Canceled（斜杠）——5 种形状一眼区分，不依赖颜色识别。

G→

双键导航（vim 派系）

G+M 跳到 My Issues、G+I 跳到 Inbox。这是 vim 用户的方言。Linear 同时也教会了非 vim 用户欣赏键盘流。

⊞

Cycle 把 Sprint 重新发明

每周/双周自动循环的 cycle，未完成自动滚到下个周期。把 Jira 那套繁文缛节用 1/10 的复杂度做完了。这是产品哲学，不是设计。

§ 05

什么时候选这个味道

Linear 的味道不是"暗色"那么简单——是"为高频快速操作的工程师做的工具"。下面告诉你它适合什么、不适合什么。

选 Linear 的味道，当你的产品是工具，用户每天高频操作。

适合
  • 工具类产品（issue tracker、CRM、工单、项目管理）
  • 用户每天打开 > 5 次的高频场景
  • 需要展现密集信息（表格、列表、看板）
  • 开发者 / 设计师 / 工程师为目标用户
  • 键盘党友好是产品差异化卖点
不适合
  • 对话 / 写作 / 阅读类产品（用户停留 = 阅读）
  • 消费级 / C 端产品（用户不会学键盘）
  • 需要"温暖、亲切"情感联结的场景
  • 移动端为主的体验
  • 追求"高级感、品质感"超过"效率感"的定位
