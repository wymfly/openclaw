§ 03

组件样本

每个组件都为"专业可信 + 数据准确 + 文档级"服务：subtle shadow + 紫色 accent + 多色 status + 强 mono。

Buttons · 带阴影立体感

Stripe 按钮的标志特征：主按钮带 2 层 shadow（一层硬一层软），让按钮"浮"起来。这是 Linear 完全不会做的（Linear 是平面派）。

Input · 强光晕

4242 4242 4242 4242
4242 4242 4242 4242

focus 时 indigo 边框 + 3px soft 光晕。这是 Stripe Elements 的标志做法，"输入此刻被关注"用强光晕表达。

Status Pills · 多色编码

Succeeded Processing Failed Refunded

浅底 + 深字的色对编码：每种状态用对应色族（绿/橙/红/灰）。比 Linear 形状编码更"金融级"——强可读、跨人群通识。

Tabs · 下划线指示

Overview
Payments
Subscriptions
Customers

细线条 + indigo 下划线，没有 pill 也没有 background。最克制的 tab 形式，让内容做主角。

Code Block · 文档基因

// Create a charge const charge = await stripe.charges.create({ amount: 2000, currency: 'usd', source: 'tok_visa', });

深蓝 #0a2540 背景的代码块，是 Stripe Docs 的灵魂。让"代码"在 dashboard 里也能优雅出现。

Alert · 信息提示

i
Test mode is active. Payments here won't charge real cards. Switch to live mode to accept real payments.

indigo-bg 浅底 + indigo 边框，icon 圆形纯色填充。Stripe 的 alert 永远配 icon + 短标题 + 一行解释——"专业产品该有的引导"。

§ 04

灵魂细节

这些是让人一眼认出"这是 Stripe"的 6 个特征。视觉好抄，"专业感"难抄。

$

tabular-nums 是宗教

所有金额、数量、ID 都用等宽数字。表格里数字纵向自动对齐，扫一眼就能比较金额大小——这是金融产品的基本素养。

⊟

多层 shadow 叠出 elevation

shadow-sm（卡片）/ shadow-md（hover）/ shadow-lg（modal）三档。Stripe 用 shadow 做层级，不靠 border。这是它"看起来高级"的核心。

⌥

渐变只用一次：在标题

整个产品几乎没有渐变。但 hero 标题的 indigo→teal 渐变文字是 Stripe 的视觉签名，出现在官网、登陆页、文档首页。

⎘

表格行 hover 暗示可点击

表格每一行 hover 变浅灰，整行可点进入详情。这是 Stripe 把"列表 + 详情"模式做到极致的结果——表格不只是显示，是导航。

📈

chart 永远配对比基线

折线图永远显示 "this period" 实线 + "previous period" 虚线。让"是好是坏"一眼可见，不需要思考。

{ }

code 是产品里的合法公民

dashboard 任何地方都可能出现 code block，配深蓝背景 + 语法高亮。Stripe 把"开发者文档"和"产品 UI"融为一体——这是它早期最大的差异化。

§ 05

什么时候选这个味道

Stripe 的味道是"专业可信 + 文档级精致 + 数据为王"。下面告诉你它适合什么、不适合什么。

选 Stripe 的味道，当你的产品需要"被相信"。

适合
  • 金融 / 支付 / 数据 / B2B SaaS（信任为王）
  • 面向开发者的产品（API 优先、文档优先）
  • 有大量表格 / 图表 / 报表的 dashboard
  • 需要"专业感、企业级"定位
  • 键鼠平衡的桌面 web 体验
不适合
  • 对话 / 写作 / 阅读类产品（太"工具")
  • 消费级 / 社交 / 娱乐产品（太"严肃"）
  • 追求紧凑高密度极速操作的工具（不如 Linear）
  • 追求温度、亲切的产品（不如 Claude.ai）
  • 移动端为主的体验（Stripe 是桌面派）
